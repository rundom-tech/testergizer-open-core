# Branding Assets

This directory contains **static branding assets** used by Testergizer-generated artifacts,
primarily the **HTML test run report**.

These assets are **repo-level**, not copied per run, and are referenced
*relatively* by generated reports under `artifacts/`.

---

## Purpose

Branding assets serve three distinct roles:

1. **Customer identity**  
   Identify the application owner / organization under test.

2. **Product identity (optional)**  
   Identify the Testergizer product visually in reports.

3. **Vendor provenance (mandatory)**  
   Clearly mark the report as generated by RunDOM Technologies tooling.

This separation is intentional and enforced.

---

## Directory Structure (Frozen)

branding/
├── customer/
│ └── customer.png
│
└── vendor/
├── product.png
└── vendor.png


### `branding/customer/customer.png`
- Optional
- Logo of the **customer / application owner**
- Displayed on the **left side** of the report header when present

### `branding/vendor/product.png`
- Optional
- Logo of the **Testergizer product**
- Displayed on the **right side** of the report header when present

### `branding/vendor/vendor.png`
- **Mandatory**
- Logo of **RunDOM Technologies**
- Displayed in the **report footer**
- Acts as a provenance marker for generated reports

> If `vendor.png` is missing, HTML report generation will fail.

---

## File Format & Guidelines

- Format: **PNG**
- Background: transparent preferred
- Recommended height (rendered): **~48–56 px**
- Aspect ratio: preserved (no stretching)

SVG is intentionally **not required** to avoid rendering inconsistencies
in file-based HTML viewing environments.

---

## Usage Contract

- Branding assets are **not copied** into `artifacts/`
- Reports reference them via **relative paths**
- A report is portable **only within the repository**
- Branding paths are **hard-coded and governed**
- Reports must never embed external URLs or base64 images

This ensures:
- deterministic rendering
- offline usability
- clear ownership boundaries

---

## Governance Notes

- Asset **paths and semantics are frozen**
- File contents may change (logo updates)
- File names and locations must not change without governance approval
- Additional branding slots must be explicitly designed and approved

---

## Non-Goals

This directory is **not** intended for:
- marketing materials
- documentation graphics
- screenshots
- per-test or per-suite branding
- dynamic theming

It exists solely to support **trustworthy, attributable test reports**.

---

## Summary

Branding in Testergizer is:
- explicit
- minimal
- non-invasive
- provenance-focused

Reports tell the truth — visually and semantically.
